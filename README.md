# Codex Multi-Session Monitor

An F:-resident, read-only monitoring wall for the existing Windows ChatGPT Codex Desktop sessions. It is built for one Android screen that can watch many sessions concurrently. It does not control, pause, resume, or rewrite Codex.

Published static shell: https://michaelunkai.github.io/codex-multi-session-monitor-pages/

Private source: https://github.com/Michaelunkai/codex-multi-session-monitor  ·  Pages-only UI source: https://github.com/Michaelunkai/codex-multi-session-monitor-pages

The hosted shell contains no Codex data or bearer token. It has the private bridge endpoint and a loopback probe range built in. When opened on the monitor PC, it probes `http://127.0.0.1` without a token and connects automatically; on another machine that probe is rejected or unreachable and the page waits for the private one-tap access link. A one-tap link carries the access fragment once; the page connects automatically, stores the token in that browser's storage, and removes the fragment from the visible address bar.

If the local monitor is starting, restarting, or chooses another free port in its reserved range, the hosted wall keeps probing and reconnects without user action. Its loopback CORS response also permits Chrome's Private Network Access preflight only for the published Pages origin; bearer authentication remains mandatory for every remote request.

## Architecture and exact versions

- Adapter/server: `2.5.4`, dependency-free Node.js production code.
- Portable Node.js: `v24.21.0` Windows x64, stored in `runtime\node` and using built-in `node:sqlite`.
- Portable PowerShell launcher: `7.6.6`, stored in `runtime\powershell`.
- Test-only DOM dependency: LinkeDOM `0.18.12`; its package cache and dependencies are under this root.
- Dashboard: local HTML/CSS/JavaScript, authenticated Server-Sent Events (SSE), 2-second polling fallback, running-only responsive live wall with a per-card live-activity line and large independent output panes. Current wall clients fetch one full running view at connection, then apply compact ordered transcript deltas to only the changed card and DOM entry. A stalled client therefore cannot accumulate repeated full transcripts, and one changing word does not make Android re-download every session. A card uses the official Desktop IPC stream when that stream publishes it; IPC-hidden child/subagent tasks use their own append-only live Codex rollout instead.
- Access: F:-resident Tailscale `1.102.3` userspace daemon plus persistent HTTPS Funnel at `https://codex-monitor.tail5cbd67.ts.net`, proxying the loopback monitor over HTTP. The monitor allows token-free protected requests only from this PC's loopback peer and loopback Host header; the public bridge never provides unauthenticated data. The hosted wall probes the loopback port range first, and the current hosted access URL for another machine is printed by `STATUS.ps1 -ShowAccessUrl` and generated by the dashboard's Copy access link button.

AgentsView and Codex Monitor HUD were checked before implementation. AgentsView is useful for local history but is not an Android-first live wall for this Desktop state; HUD is a Windows overlay and uses `%LOCALAPPDATA%`. The current Desktop build exposes an official per-user read-only follower channel at `\\.\pipe\codex-ipc`. The monitor attaches to that existing channel, follows known session IDs, replays its snapshot/JSON-patch stream, and never starts a second app-server or sends turn/control requests.

## What is shown

The API and UI are deliberately locked to **RUNNING NOW**. A card is sent only when all of these are true:

1. The official Desktop IPC state identifies a current in-progress turn, or the task's append-only Codex rollout has `task_started`, no matching completion, and a fresh write. The second path is required for current Codex child/subagent tasks that the Desktop IPC pipe does not publish.
2. A current turn id is known.
3. The Desktop stream or the task's own rollout has current activity inside the configured live window.

Completed, stale, interrupted, cancelled, failed, archived, and historical sessions are not rendered as cards. When the connected Desktop stream reports that a followed turn is no longer in progress, that card is removed immediately even if an old SQLite or rollout row still says `inProgress`. For an IPC-hidden task, its own `task_complete` record or 20 seconds without a fresh rollout write removes the card. They are counted as hidden history in the summary only. A historical database row, a live-looking process name, or an old `inProgress` flag cannot by itself make a session appear RUNNING.

Each card shows the title, project, model/source, working directory, current turn id, current live activity, last event time, elapsed time, output character count, and the current turn's complete durable output entries. Assistant messages, command output, tool results, and other user-visible rollout text are displayed in large independently scrollable transcript panes with whitespace preserved. The UI uses one column on narrow Android screens and a minimum 480-pixel card width on larger screens, so ten or more cards remain readable by scrolling the wall rather than compressing them into tiny tiles. The live-activity line identifies fresh events such as writing a response, running a command, running a tool, thinking, token-usage work, or streamed output when a delta record is available.

## Output and real-time reliability

The primary path is the existing Desktop IPC stream. It receives conversation snapshots and patches for each followed session, including the same agent-message and command-output text updates that the Desktop remote conversation reducer consumes. The adapter replays those patches in memory and preserves the exact current user-visible text (with whitespace). Codex currently does not publish some child/subagent task states on that pipe; for those tasks the adapter tails only that task's own append-only rollout JSONL, including `agent_message_delta` text as it is written, durable messages, command output, and tool output. It does not mix SQLite item history into the transcript for that path. A current wall client fetches one full authenticated snapshot, then receives an ordered `delta` SSE frame containing only added/removed cards and changed output fragments. Growing entries use appended text instead of a replacement copy, and the browser patches that single transcript node in place. A missing/out-of-order delta automatically triggers one full re-sync. The browser reconnects automatically and falls back to polling if its SSE connection drops. There is no manual refresh requirement during normal operation. The old full-snapshot and revision-only SSE modes remain only for already-cached pre-2.5 wall assets during their transition.

Desktop cards are marked `liveTransport: codex-ipc`, with output/activity `source: codex-ipc`. IPC-hidden child/subagent cards are marked `liveTransport: codex-rollout-live`, with output/activity `source: rollout`; every displayed rollout entry is checked against that task's current local rollout in the live proof. Both paths are running-only and freshness-gated. Common credential-shaped strings are redacted before leaving the adapter. A 5,000,000-character per-session safety ceiling prevents one pathological file from exhausting the monitor.

Reliable IPC facts: current in-progress turn, exact current agent-message/command-output text exposed by Desktop, live activity kind, turn ID, elapsed time, project, and working directory. Reliable rollout-live facts: the child task's own unfinished rollout state, exact appended output text, and fresh local activity. A rollout card can lag an in-memory Desktop rendering only until Codex appends its next rollout record (the monitor polls every 500 ms); it is never presented as IPC. The wall does not invent approval, failure, or stuck states. Official Codex Remote remains the control path for opening and operating an individual task.

## Detection sources

The adapter opens these existing Codex files read-only:

- `C:\Users\micha\.codex\state_5.sqlite`: non-archived thread metadata, title, project/working directory, model, timestamps, and rollout path.
- `C:\Users\micha\.codex\thread_history_1.sqlite`: thread/turn metadata and plan-progress projection; it is not used as a transcript source for rollout-live cards.
- `C:\Users\micha\.codex\session_index.jsonl`: official renamed titles when present.
- The referenced rollout JSONL files under `C:\Users\micha\.codex\sessions`: live task and output events.
- The official Desktop per-user IPC pipe `\\.\pipe\codex-ipc`: read-only stream-following snapshots and patches for candidate session IDs.

No Codex file is written, copied, relocated, or opened for exclusive access. Existing paths outside F: are source inputs only. The IPC observer sends only the official follow/unfollow broadcast used by the Desktop remote view; it does not send prompts, approvals, tool calls, or other control messages. Rollout-live cards are a separate exact source for IPC-hidden tasks. Optional diagnostic logs are never allowed to keep a card visible or substitute for its own fresh rollout write.

## Start, stop, status, and restart

Use the obvious wrappers from any normal Windows shell:

```powershell
& 'F:\backup\windowsapps\installed\Codex-MultiSession-Monitor\scripts\START.cmd'
& 'F:\backup\windowsapps\installed\Codex-MultiSession-Monitor\scripts\STATUS.cmd'
& 'F:\backup\windowsapps\installed\Codex-MultiSession-Monitor\scripts\HEALTH.cmd'
& 'F:\backup\windowsapps\installed\Codex-MultiSession-Monitor\scripts\STOP.cmd'
```

The wrappers force the portable F:-resident PowerShell runtime; this avoids Windows PowerShell 5.1 certificate-option differences. START sets TEMP/TMP and package caches under F:, validates the portable runtimes and source paths, binds the monitor to loopback HTTP for zero-certificate PC startup, avoids duplicate monitor instances, selects a free port, starts the monitor and private bridge, waits for authenticated full health, and never prints the bearer token. The supervisor uses a separate authenticated lightweight liveness probe so a large telemetry snapshot cannot trigger a false restart, and re-establishes the bridge after monitor or daemon recovery. On the PC itself, opening the published wall probes loopback automatically with no access link; `STATUS.cmd -ShowAccessUrl` is only for another machine. Restart is STOP followed by START. All controlled logs are under `logs`.

Automatic startup is registered in the current user's Windows Run key as `Codex-MultiSession-Monitor`. Its value invokes Windows' built-in Script Host only to run the F:-resident `scripts\AUTOSTART.vbs` shim, which starts the portable F:-resident PowerShell `START.ps1` launcher detached from transient launcher jobs. No project wrapper, package, service, or project file is placed outside F:. START waits for the monitor and private bridge to become healthy, then leaves their F:-resident supervisor running. The supervisor launches the monitor immediately on its first failed health probe and restarts it after later health failures. STOP intentionally signals the supervisor to exit. Use `ENABLE-AUTOSTART.ps1` and `DISABLE-AUTOSTART.ps1` to manage that one Run value. This Run-key value is the only intentional OS registration outside F:; no global PATH change, firewall rule, or certificate-store entry is installed.

## Android: exact use

1. On the PC, run `F:\backup\windowsapps\installed\Codex-MultiSession-Monitor\scripts\START.cmd` (or use the already-running monitor). The published Pages URL is the default PC wall; it probes the loopback monitor automatically and does not require a bearer link. The direct local address printed by STATUS is `http://127.0.0.1:<port>/`.
2. On Android or another machine, open the private **one-tap hosted access link** shown by `STATUS.cmd -ShowAccessUrl` or copied by the dashboard's `Copy access link` button. It opens the published Pages wall, targets the stable private bridge automatically, authenticates once, and immediately renders the running-only cards. Do not share that link.
3. No same-Wi-Fi requirement or local certificate exception is needed: the bridge uses Tailscale's HTTPS endpoint. Cellular access works while the PC is online and the Funnel node remains connected.
4. After the first successful open, bookmark the bare Pages URL. The token is retained only in that browser's local storage, the URL fragment is removed, and that device reconnects automatically after refresh or a monitor restart. A new device must receive a fresh copied one-tap link once; it will then retain its own local authorization.
5. Leave the wall open: authenticated SSE updates automatically, with polling fallback. Scroll vertically to inspect every running session; scroll inside each card's transcript pane to read its current output.

On the monitor PC itself, opening the published Pages URL above connects to the loopback feed automatically without a bearer link. The Pages URL uses the loopback probe only on the PC; Android and other machines must use the private one-tap link.

Use the one-tap hosted URL, not the bare IP/port. Do not share it: it contains the bearer token. The token is not in GitHub, Pages, or the project source. The stable Funnel hostname is independent of the PC's LAN IP and monitor port. Access remains dependent on the PC, the F:-resident bridge, the Tailscale account/device authorization, and the token; disabling the device, resetting browser storage, rotating the token, or deleting the project invalidates access.

## Security model

The server binds only to the PC loopback interface and uses HTTP there because loopback is not a network listener. Protected health, snapshot, and SSE requests are token-free only when the TCP peer is loopback and the Host header is the loopback monitor address. Tailscale Funnel supplies the stable public HTTPS transport; all Funnel and other-machine requests still require the bearer token and a random internet visitor receives 401. The static shell contains no session data; its local endpoint is only a non-secret loopback hint. Token ACLs are limited to the current user and SYSTEM. The one-tap URL is a private bearer link; the token is not in GitHub or Pages and is moved to browser local storage, then removed from the visible URL after connection. No unrestricted LAN listener, SMB/RDP rule, firewall weakening, or authentication bypass was added.

Windows and Codex may create unavoidable metadata outside F:. This project redirects its runtimes, dependencies, caches, temporary files, configuration, state, logs, certificates, and scripts to this root wherever technically controllable. The existing Codex installation and state were preserved.

## Troubleshooting

- **PC shows Token needed:** confirm `START.cmd` and `HEALTH.cmd` are healthy, then reload the published wall. It probes `http://127.0.0.1` ports `8765` through `8800` without a token and uses the first healthy monitor; no certificate exception or access token is required on this PC.
- **Published Pages shell on the PC shows Token needed:** no healthy loopback monitor was found. Run `START.cmd`, confirm `HEALTH.cmd`, and reload the bare Pages URL.
- **Android/remote shows 401 or Token needed:** reopen the private one-tap URL from the handoff. If the token was intentionally cleared or browser storage was reset, generate a new private link with `STATUS.cmd -ShowAccessUrl`.
- **Certificate warning:** the hosted Funnel URL has a public HTTPS certificate. A certificate warning on the hosted URL indicates a wrong URL or a broken bridge and should not be bypassed.
- **No cards:** STATUS should report `RunningSessions`. Confirm `summary.liveTransport.connected` and `initialized` in `/api/health`. A session is hidden immediately after the direct Desktop stream reports its turn complete, or after the 20-second rollout-live freshness window expires.
- **Direct stream unavailable:** inspect `summary.liveTransport.lastError` and confirm the official Codex Desktop process is still running. The monitor reconnects to `\\.\pipe\codex-ipc` automatically. An IPC-hidden task can remain visible only while its own rollout is still unfinished and freshly appending.
- **No Android connection:** run `STATUS.cmd`; `PrivateBridgeLoggedIn` must be `True` and `PrivateBridgeUrl` must be populated. Then use a newly generated `STATUS.cmd -ShowAccessUrl` link. No global firewall change is made automatically.
- **Published shell cannot connect:** on the PC, confirm a healthy `http://127.0.0.1` monitor and reload; on another device, use the one-tap hosted URL rather than the bare URL. Confirm the PC is online and inspect `logs\tailscaled.stderr.log` and `logs\supervisor.log`. The bridge is deliberately bearer-protected, so a bare Pages URL cannot display sessions on a remote device.
- **Bridge shows logged out:** run `START.cmd`; it will print/open the current authorization URL when one is required. Approve it once, then the F:-resident `tailscale up --unattended=true` state and Funnel configuration persist across launcher restarts and Windows logoff.
- **Telemetry errors:** inspect `STATUS.ps1`, `logs\server.stderr.log`, and the current Codex source paths. A nonzero telemetry-error count can represent old/missing rollout references and does not turn stale sessions into RUNNING cards.
- **Need to act on a task:** use official Codex Remote or the Codex Desktop app; this dashboard is read-only.

## Uninstall

Run `DISABLE-AUTOSTART.ps1`, then `STOP.cmd`. Confirm the exact F:-resident monitor and bridge processes are stopped. If you also want the Funnel publication removed from the Tailscale node before deletion, run the F:-resident `tailscale.exe --socket=\\.\pipe\CodexMultiSessionMonitorTailscale funnel reset` while the bridge is running, then run `STOP.cmd`. If removal is desired, delete only this exact directory:

`F:\backup\windowsapps\installed\Codex-MultiSession-Monitor`

Do not remove `C:\Users\micha\.codex`, the WindowsApps Codex installation, or any other path. No system service, firewall rule, or certificate-store item belongs to this project.

## Safe updates

Keep all new archives, caches, temporary files, dependencies, and build output under this root. Review changes to `app` and `scripts`, copy the three `app\public` assets to both `deploy` and `public-site`, run `scripts\SYNC-PUBLIC-ENDPOINT.ps1` when the stable bridge hostname changes, run `scripts\TEST.cmd`, restart, then run `tests\live-proof.js`, `tests\recovery-proof.ps1`, `tests\android-network-proof.js` when the authorized Android transport is available, and `scripts\AUDIT.ps1`. Push the private source repository and the Pages-only checkout only after the tests pass. Before installing any package, set `TEMP`, `TMP`, `NPM_CONFIG_CACHE`, `NPM_CONFIG_PREFIX`, and `XDG_CACHE_HOME` to the project directories. Never use a global install or the system Node/Python installation.

Validation records are kept under `logs` and the source findings under `findings.md` and `task_plan.md`. The approved visible Chrome connector was unavailable during the PC run, so browser pixels were not claimed as verified; the authenticated HTTPS/SSE path is proven from the PC, while final phone-pixel confirmation remains dependent on an attached authorized Android transport.
